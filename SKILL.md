# Sales enablement

1. Read existing `.agents/product-marketing.md` or legacy `.claude/`/`product-marketing-context.md` if present. Identify the requested asset, audience, deal stage and available proof. Ask only for missing facts needed by this asset; one objection does not require a sales audit.
2. Load only matching guidance:
   - Deck → [deck frameworks](references/deck-frameworks.md).
   - One-pager → [templates](references/one-pager-templates.md).
   - Objection document → [objections](references/objection-library.md).
   - Win/loss → [research](references/win-loss-analysis.md).
   - Demo/call → [demo](references/demo-scripts.md) or [cold-call](references/cold-call-scripts.md).
   - Proposal, case study, ROI, playbook, persona, live objection → matching section in [asset guidance](references/asset-guidance.md).
3. Write for that situation. For a live objection, give one sayable response, supported proof if available, and a useful follow-up. Use defensible benefits; label unproved advantages/ROI as assumptions. Competitor claims need dated sources; absence from a site is not proof a feature does not exist. Include where the competitor fits better. Never invent testimonials, metrics or entitlements; preserve the user's established prices and never offer unrequested discounts.
4. Deliver the requested format. A file request requires an actual deck/document/sheet using an available format skill, with Sarabun unless otherwise requested; an outline alone is insufficient. A one-pager must fit one page. ROI must show inputs, assumptions and formulas.
5. Check audience/scope, proof, calculations and final format. Sending materials, contacting people or updating CRM needs authorization for that action. Optional upstream skills/integrations are not prerequisites when absent.
